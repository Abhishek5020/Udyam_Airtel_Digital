2. Consent (s.6 DPDP)

  • A consent screen in the owner's chosen language appears before any document upload. It lists each purpose separately: KYC and installation are required; WhatsApp marketing is optional and off by default.
  • Each consent is written to a purpose-tagged consent ledger (consent ID, purposes, language, timestamp, retention text) and linked to the order.
  • Withdrawal is one tap from the tracker. It triggers deletion of document images and stops optional processing; only records the law requires are kept.

3. Minimising exposure

  • Masking everywhere: GSTIN, Udyam and ID numbers show only the first 2 and last 3 characters (e.g. 37••••••••••1ZU) in the UI, API responses and logs.
  • In-memory processing: uploaded images are OCR'd in memory and not written to disk in the prototype. In production they go to an encrypted, access-logged object store.
  • Audit log records every registry lookup, consent and KYC verdict with masked identifiers only. The back office never sees full IDs.
  • Role-based access: Saathis (field and partner) see leads, scores and drop reasons, never documents. Only the KYC reviewer role can open a flagged document.
  • The propensity model uses business attributes only (segment, size, source, spend). No personal attributes, so there's no profiling of individuals.

5. Security controls

  • TLS 1.2+ in transit and AES-256 at rest. Secrets are kept in a vault and never in code. Registry, DigiLocker and e-Sign calls go only over signed server-to-server APIs.
  • KYC integrity: GSTIN mod-36 check digit, registry status (cancelled/suspended blocked), cross-document name/state/date checks, blur and skew detection. Uncertain cases go to a human (NEEDS REVIEW) instead of being auto-approved.
  • GenAI safety: the language model never sees documents or identifiers and cannot choose products. A deterministic rules engine decides eligibility.
  • Rate limits on lookup APIs prevent GSTIN enumeration. File-type and size checks run on uploads.

6. Data principal rights & grievance

  • Access, correction and erasure from the tracker or helpline 121. A named Grievance Officer responds within the statutory timeline. Breaches are notified to the Data Protection Board and affected owners as DPDP requires.
